# Feedback → improvement → retest

## Invite
Ask someone to import a model and take it into the dungeon. Ask for a short clip, one thing that worked and one obstacle. GitHub issues are the shared inbox. Local-only feedback is not centrally visible. No analytics or automatic upload runs in this build.

## Triage
Review new issues manually. Acknowledge the report; reproduce bugs with a shareable model; link duplicates. Note affected step (install/import/convert/play/export), frequency among reports, impact and a smallest useful change. Keep observations separate from guesses. A report is not a measured unique user.

## Choose
Prefer blockers, lost progress and recurring friction over new features. Pick one small improvement at a time. For bigger changes, describe the success condition in the issue before coding.

## Verify and close the loop
Reference the issue in the change, run relevant checks, inspect visual changes in the browser, then reply with the commit and retest steps. Invite the reporter to confirm. Distinguish developer verification from reporter confirmation. This is a manual workflow; no bot automatically modifies code or contacts reporters.

## First experiment
Targets: five independent runs, three shared creations, one contributed improvement. These are not achieved results. Keep a simple weekly note with voluntary reports, successful imports/dungeon entries, recurring obstacles, changes shipped and retest results. Do not infer usage or payment intent from stars or views.
